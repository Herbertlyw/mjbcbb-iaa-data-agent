# Lumenfox Data Agent

这是一个可在本地运行的只读数据分析代理。当前在线主链是 TypeScript：Pi SDK 负责工具调用循环，服务端负责权限、契约绑定、SQL 校验、会话资源和任务终态。

演示场景是虚构工作室 **Lumenfox Interactive** 的手游 **Starlane Drift**。表、指标、SQL、账号和数字都是合成的。默认模式不会访问外部模型，也不会连接真实业务库。

## 本地启动

需要 Node.js 22.12 或更新版本。安装依赖时使用 `--ignore-scripts`，并保留 `package-lock.json`。

```bash
npm install --ignore-scripts
npm test
npm run typecheck
npm start
```

浏览器打开 `http://127.0.0.1:4317`。页面可以新建会话、提问、追问，并看到运行中、完成、需要澄清、部分完成、失败、已取消和已超时。

也可以运行 `npm run demo:stack` 启动隔离的分进程协议演示。它使用本机已存在的 ClickHouse、MySQL 和 Redis 镜像（不自动拉取），随机分配回环端口，在 tmpfs 中创建合成数据库和一次性凭据，然后发布 freshness 并启动 API、dispatcher 和 worker。终端打印的地址才是本次访问地址；按 Ctrl+C 停止并清理本次创建的容器和临时文件。默认固定使用 2026 年 10 月的合成数据；`npm run demo:stack -- --rolling` 按洛杉矶当前业务日整体平移合成数据并使用滚动 freshness，`--rolling --today=2027-02-15` 可注入可复现测试日期。跨业务日后须重启滚动演示以生成新样本和发布，旧 freshness 不冒充当前结果。两种方式都使用脚本假 HTTP 模型，适合验证预置问题及协议，不代表真实模型理解或泛化；脚本里的日期平移不会改写 Pi 会话中的用户原话。不要直接双击 HTML 文件。

配置示例在 [`.env.example`](.env.example)。不要把真实密钥写入仓库。`MODEL_MODE=deterministic` 是确定性演示；`MODEL_MODE=pi` 使用 Pi AgentSession，可选择显式 `faux` 或 `openai-compatible` 本机协议假服务。后者仅允许 `http://127.0.0.1`，需要虚构测试 token；脚本服务不代表真实模型联调。Anthropic 和远程 HTTPS 路径当前禁用，不会自动回退到 faux。

本地文件写到 `.local-runtime/`，该目录已被忽略。合成业务库存 `lumenfox.sqlite`，每次启动重建并以只读方式打开。

有两种本地模式，不要混称：

- `npm start` 是 SQLite 单进程演示。业务查询打在本地 SQLite，状态也在本进程。这不是 ClickHouse 验证。
- `BUSINESS_ENGINE=clickhouse` 时，业务查询打到 `127.0.0.1` 上的隔离 ClickHouse，使用只读账号。表卡在 `knowledge/harborlight/`。MySQL 仍只存任务状态，Redis 仍只做调度。不要把 SQLite 演示说成 ClickHouse 验证。

## 这条主链做什么

一次提问会经过：

1. 确定性演示模式会把用户原话编译成已发布语义文件里的槽位。`MODEL_MODE=pi` 把用户原话和同会话历史送进同一个 Pi AgentSession，不在模型调用前强制套用这层槽位，也不会在缺少密钥时退回演示逻辑。
2. Pi Agent 循环调用 8 个工具：`search_assets`、`read_asset`、`read_assets`、`read_data_contract_view`、`query`、`calculate_session_cells`、`read_session_resource`、`update_analysis`。
3. 搜索返回资产卡片与授权正文的命中片段，稳定续页校验结果哈希；正文只参与当前主体可读资产的检索匹配。`read_assets` 可批量读取各资产的 Unicode 码点分页，逐项检查内容哈希；契约字段可分页并显示已发布新鲜度。查询资源可按行和列分页，资源截断与页面续读分别标记。
4. `query` 在只读连接上解析单条 SELECT，并递归检查 CTE、子查询和联合查询里的表、字段、敏感列、契约版本和封闭日期。单表日期支持等值、`BETWEEN` 和上下界；宿主另限制 SQL 为 64 KiB、日期范围为 400 天，超出拒绝。JOIN 检查登记键与契约粒度；无法确定粒度及不支持的语法会被拒绝。严格限定的单事实表与维表 INNER / LEFT JOIN 子集在查询中捕获证明元组，检查事实粒度、实际类型、重复键和结果，并将实际匹配的维表键值与已发布的维表摘要核对；标签筛选之前检查维键重复。LEFT JOIN 固定启用 join_use_nulls，未匹配键须被完整发布快照证明缺失，结果保留 NULL；执行 SQL、设置及捕获结果共同绑定。单层单表 CTE 或派生表仅在内外都是直接投影、过滤仅在内层且可独立证明等价时可进入证据；实际仍执行原 SQL。受限单层 CTE 或派生表可先按事实契约粒度的子集预聚合最多八个受限整数或 Decimal SUM，再关联登记维表并求和；须保留登记键并逐个已观察事实键验证整段日期覆盖和唯一性；系统保存用户原 SQL，实际执行经过严格等价展开且附证明元组的 SQL，验证使用实际执行记录。不满足约束的形状拒绝。解析器仍是受限 SQLite 方言 AST，并非完整 ClickHouse AST；事实表直接 JOIN 暂不支持。维表探测记录的是受限字段的观察摘要，而不是跨表原子快照，缺少有效回执或无法证明时失败关闭。单事实表的受限整数及 Decimal `SUM`、非 NULL `COUNT` 和最多三个契约维度分组可验证已捕获值；未出现的组合不补零。
5. 服务端根据证据决定终态。模型写出的“已完成”不会单独生效。契约声明了粒度时，无记录、值为 NULL、观测零和预测值分开；无记录和 NULL 不会补成零。存在这些缺口或覆盖情况未知时，数据结论是部分完成。覆盖统计目前仅能证明单表、日期上下界及序列维度字面量等值筛选；其他筛选或多表查询标为未知。`update_analysis` 可比较两个本任务计算单元，或两个可唯一定位的 Decimal 汇总输出：要求完整覆盖和相同口径，范围只能差一个维度或两个等长不重叠日期段；差值用定点整数运算，比例保留四位、变化率保留两位，半数远离零，零基准不计算比例和变化率。原有浮点金额仍只是近似值。查询只读已发布的新鲜度快照，不在提问时用最大日期冒充。身份来自服务端标明的 mock 主体，不信任请求正文里的 userId。

ClickHouse 结果按行和字节上限流式读取：预览缩短不会截断已保存结果；超过保存上限时标记截断，观察到的行数只是下界。SQL 中的 `LIMIT` 也不视为完整总体。单元计算可使用完整资源，Decimal 明细在物理类型及契约可核验时按字符串精确求和；全 NULL 和无行求和不是零，未知预测状态不伪装为实际值。

受限预聚合 JOIN 还可穿过最多八层仅做一对一列投影和重命名的 CTE 或派生表；各层不能隐藏过滤、排序、额外聚合或截断。详细证明超过预算或不能验证时，可重新执行一个只读的聚合级证明：在数据库对本次观察的事实粒度、维键重复和 NULL 指标做全量检查，并保存有界维表观测及实际执行回执。它不传回所有事实元组，不证明缺失日期或未出现的分组；这种结果按覆盖未知部分交付，也不宣称两次查询是同一快照。受限制的 JOIN SUM 结果可逐行计算契约明确声明方向的指标比率；不支持的关系拒绝，NULL 和零分母不能补零。

四则运算可引用本任务受支持的聚合单元、完整明细的指定行或整列，以及已验证计算结果；明细引用须匹配执行 ID，交付时递归核对资源、权限、契约、新鲜度、覆盖和结果。跨指标公式只接受契约明确声明的有向关系与兼容口径；除法保留 18 位小数，半数远离零，除零返回不可计算。已验证 JOIN、聚合和受限直接投影支持结构化筛选、列比较、排序及分组变换，也可按键全集对齐，缺组和 NULL 不补零。单表直接明细可先在服务端基于全部哈希绑定分页按契约维度精确汇总再跨资源对齐；一侧也可使用经核验的数据库分组 SUM。该路径区分 NULL 键与字符串、全 NULL、部分 NULL、缺侧、零和零分母，输入覆盖不完整会随派生结果传播为部分完成；NULL 键的周期覆盖不能证明，因此保守降级。跨事实表仅接受契约显式声明的有向指标关系、相同维度类型和粒度与一致范围；不是用户归因。完整资源计算及各中间结果最多 10,000 行、2,000,000 字节和 10 步；默认查询保存上限同为 10,000 行和 2,000,000 字节，模型和页面只收到标明总数的有界预览，可按资源续页。明细变换限于受支持整数或 Decimal、契约声明仅观察值的直接投影；不支持的表达式、浮点及无法证明预测状态的输入会拒绝，而非样本冒充完整结果。普通 ClickHouse 查询与覆盖是独立读取，多次查询之间无共同快照保证；满足现有检查时可以完成交付，同时说明这个限制。同范围覆盖观测实际冲突时只能部分交付。模型未调用 `update_analysis` 时，服务端可从本任务可核验资源生成部分完成结果，仍不会采信自由文本作为已验证事实。

`update_analysis` 可附模型自报的范围、粒度、问题和假设；这些内容在页面独立标明为工作记录，不作已验证事实。知识摘录须与当前可读资产的内容哈希和原文匹配，但不证明摘录适用或此前已读；结果单元引用须属于本任务的完整授权直接投影且匹配执行 ID，由服务端取值。知识目录、权限、JOIN 规则及相关资产文件会在读取、计算与交付前异步重核；文件检查与后续操作不是原子事务。终态提交前会重新核对候选记录所引用的资源哈希、授权、契约和已发布新鲜度；旧版未包含资源哈希的中断候选无法通过此检查，需要重新执行，不会悄悄升级为已核验结果。

知识在 [`knowledge/lumenfox/`](knowledge/lumenfox/)，区分资产目录、表契约、指标口径、分析 SOP、示例 SQL 和权限政策。`registry.json` 里的 `registry_revision` 和各资产 `revision` 是修订标识。

## 明确还是模拟的部分

本地实现有可替换的 `StateStore`，默认是单机 SQLite。这不是分布式生产方案：

- 保证限于同一台机器上的一个状态库。领取使用 `BEGIN IMMEDIATE` 和递增围栏号；心跳只续当前围栏的租约。
- 进程重启后，租约过期且尚未终态的任务可以被新执行者回收。旧围栏不能再写事件或终态。
- SQLite 演示没有多机共识。MySQL 模式的终态由事务和围栏保证只有一个；outbox 到 Redis 是至少一次投递。worker 在写完终态前崩溃时，合成查询可能再执行一次，这不是整个外部副作用的 exactly-once。
- SQLite 状态模式的新鲜度仍发布到本机文件。MySQL 状态模式由独立探测进程先登记批次，再把整批结果和发布指针写入 MySQL 事务；查询和交付只读取 MySQL 发布版本，数据库不可用、版本缺失或契约/目标清单不匹配时失败关闭，不回退旧文件。`/api/health` 的 `freshness_status` 区分已发布、未发布、清单变化和不可用；已发布不代表每张表都是 fresh。旧文件不会自动迁移，需要对隔离库重新探测。
- MySQL freshness 通过数据库分配的批次序号决定先后，较早开始的批次不能覆盖较晚批次。已发布版本及未完成批次保留供排查，本构建不自动删除历史。最终终态事务锁住发布指针并核对可交付证据版本，与发布事务排序；版本已变时任务失败且不保存旧结论。事实表探测核对日期是否存在；NULL、真实零和预测状态由后续查询覆盖检查区分，日期存在不证明指标完整。维表探测对声明的非敏感列最多读取 1000 行及 2 MB，检查键唯一后发布键值摘要；该观察时间不是外部同步时间，也不能证明数据库不可变。过期判断默认采用当前时间及知识包/契约时区，`SIMULATED_TODAY` 只用于注入合成测试日期。默认目标仍是固定合成日期；可选的 `knowledge/harborlight/freshness-targets-rolling.example.json` 使用契约时区、延迟和窗口计算周期。跨日时旧版本清单不再匹配，须重新探测；固定历史数据没有覆盖新周期会标为不新鲜。终态事务尚未原子复核跨午夜有效期、契约文件变更或主体权限变更。
- 业务库可以是本地只读 SQLite 演示或隔离的本地 ClickHouse 合成库；MySQL 只存任务状态，Redis 只负责唤醒。
- 确定性模型走 Pi SDK 的 faux provider，不发网络请求。`MODEL_MODE=pi` 的真实模型路径仍未联调。
- 独立 API、dispatcher、worker、Pi 快照与领域工具使用 Promise 状态桥；MySQL 旧同步入口立即拒绝调用，SQLite 演示保留本机同步实现。单桥最多 64 个在途请求，超时或关闭时相关写入结果可能未知，桥会失效，后续由运行时重建；不能假定事务回滚或盲目重试。模型派发先预留、结算后才交付终止事件；Pi 快照按序等待保存，续租不重入。MySQL 租约和保护性写入使用数据库时间。进程内订阅只通知本 worker，不替代可持久续读的 MySQL/SSE 事件；异步不保证数据库故障或容量耗尽时仍低延迟，也不等于多机高可用。
- 知识正文读取字节预算目前只保存在执行进程内，进程重启后不会保留，不能作为跨恢复的权威配额；工具调用预算和模型预算另行持久化。JOIN 捕获内容的哈希只是内容标识，信任状态库，不能防止有权写状态库的人同时改写证明和哈希。
- 客户端断开只停止事件流。用 `after` 序号可以有序续读已经落库的事件。取消必须调用取消接口。

MySQL 分进程模式需要先配置本机隔离 MySQL、Redis 和 ClickHouse，并准备合成数据与只读账号；按照 `.env.example` 为各进程设置相同的本机配置后，先运行 `npm run start:freshness`，再分别运行 `npm run start:api`、`npm run start:dispatcher` 和 `npm run start:worker`。首次使用 MySQL 需要允许初始化状态表与 freshness 表。也可使用上面的 `npm run demo:stack` 创建并清理本次隔离演示资源；手动停止服务和清理测试实例时应只处理自己创建的资源。

要试用滚动示例，所有进程需一致设置 `KNOWLEDGE_DIR=knowledge/harborlight` 和 `FRESHNESS_TARGETS_PATH=knowledge/harborlight/freshness-targets-rolling.example.json`，然后重新运行 freshness 探测。固定合成仓库可在测试中设置 `SIMULATED_TODAY=2026-10-29`；不设置则使用当前日期，不会把旧数据冒充当前数据。

也可用 `npm run seed:clickhouse` 在**本轮新建、回环端口的隔离 ClickHouse** 内建立新的滚动合成库。先通过环境变量提供 `CLICKHOUSE_URL`、`SYNTHETIC_DATABASE`、`SYNTHETIC_ADMIN_USER`、`SYNTHETIC_ADMIN_PASSWORD`、`SYNTHETIC_READER_USER`、`SYNTHETIC_READER_PASSWORD`；数据库和只读账号名须以 `synthetic_` 开头，口令使用本轮临时生成的字母数字。该命令只创建新数据库及只读账号，不清空或覆盖已有数据库；失败时保留部分初始化结果供检查。接着将应用的 ClickHouse 库名、只读账号与口令指向新库，再启动 freshness、API、dispatcher 和 worker。生成器默认按洛杉矶当前日平移完整合成样本，保留 NULL、真实零和预测；`SIMULATED_TODAY` 可固定测试日期。滚动窗口的示例延迟是合成规则，并非实时业务数据。

仓库里的 `showoff/`、`data_agent_plan/`、`da_assets/` 和 `bugfix_doc/` 是历史公开材料。它们帮助理解边界；和当前 TypeScript 主链冲突时，以这里的运行代码和测试为准。

### 图的更新

图以 `.excalidraw` 为可编辑源；修改源文件后运行：

```bash
npm install
ruby scripts/重新导出架构图.rb
ruby scripts/校验公开快照.rb
```

图像只应由当前已脱敏源重新导出，不应复用私有工程中的旧 PNG。导出图依赖 `sharp`，这一步不能使用 `--ignore-scripts`。数据分析代理本身不需要这些安装脚本。
