# Lumenfox Data Agent

这是一个可在本地运行的只读数据分析代理。当前在线主链是 TypeScript：Pi SDK 负责工具调用循环，服务端负责权限、契约绑定、SQL 校验、会话资源和任务终态。

演示场景是虚构工作室 **Lumenfox Interactive** 的手游 **Starlane Drift**。表、指标、SQL、账号和数字都是合成的。默认模式不会访问外部模型，也不会连接真实业务库。

## 本地启动

需要 Node.js 22.12 或更新版本。安装依赖时使用 `--ignore-scripts`，并保留 `package-lock.json`。

```bash
npm install --ignore-scripts
npm test
npm run typecheck
npm start
```

浏览器打开 `http://127.0.0.1:4317`。页面可以新建会话、提问、追问，并看到运行中、完成、需要澄清、部分完成、失败、已取消和已超时。

也可以运行 `npm run demo:stack` 启动隔离的分进程协议演示。它使用本机已存在的 ClickHouse、MySQL 和 Redis 镜像（不自动拉取），随机分配回环端口，在 tmpfs 中创建合成数据库和一次性凭据，然后发布 freshness 并启动 API、dispatcher 和 worker。终端打印的地址才是本次访问地址；按 Ctrl+C 停止并清理本次创建的容器和临时文件。默认固定使用 2026 年 10 月的合成数据；`npm run demo:stack -- --rolling` 按洛杉矶当前业务日整体平移合成数据并使用滚动 freshness，`--rolling --today=2027-02-15` 可注入可复现测试日期。跨业务日后须重启滚动演示以生成新样本和发布，旧 freshness 不冒充当前结果。未指定 `--local-model` 或 `--deepseek` 时，这两种方式使用脚本假 HTTP 模型，适合验证预置问题及协议，不代表真实模型理解或泛化；脚本里的日期平移不会改写 Pi 会话中的用户原话。不要直接双击 HTML 文件。

可加 `--large`（例如 `npm run demo:stack -- --large --rolling --today=2027-02-15`）在本轮临时 ClickHouse 内额外生成 100,000 行虚构安装数据，再点击“十万行（大样本模式）”。生成不写出数据文件，不连接已有数据库；四天、两个渠道每日日分组分别为 156250000 和 156262500，总计 1250050000。默认未启用大样本时该示例不会有这批数据。实际完成或部分完成取决于查询时能否证明所需覆盖，合成期望不是授权或 freshness 的替代。

将来如需自行使用本机 OpenAI 兼容服务，可在启动进程前仅在本机设置 `PI_BASE_URL`、`PI_MODEL`、`PI_CONTEXT_WINDOW` 和 `PI_MAX_OUTPUT_TOKENS`，再运行 `npm run demo:stack -- --local-model`。如服务需要令牌，可在本机额外设置 `PI_API_KEY`；未设置时使用虚构占位令牌。地址必须是带端口的 `http://127.0.0.1`，不能携带 URL 凭据或查询参数。启动器不会扫描或预先探测模型服务，不会打印令牌；请勿把真实令牌发进对话或提交仓库。用户配置的服务与模型能力未验证，其返回的用量标为 `reported`（服务自报），缺失用量仍标记未知并保留预算。可用 `PI_REASONING` 和 `PI_ENABLED_REASONING` 配置支持的档位；模型是否兼容工具调用需由用户自行验证。

`npm test` 将测试文件并发限制为 2，减少本机同时启动多套数据库容器的资源压力；单个测试内部的并发、故障和恢复断言仍会执行。

DeepSeek 合成数据验证可在本机设置 `DEEPSEEK_API_KEY`，或使用 Git 忽略的 `.local-runtime/deepseek-api-key` 文件，并先显式创建跨任务预算，再运行隔离栈。密钥文件必须是当前用户拥有、仅本人可读的普通文件（建议权限 `0600`），不能是符号链接；环境变量优先。不要把密钥发到对话或提交仓库。该选项使用新建的隔离服务和合成 Harborlight 知识，默认模型为 `deepseek-flash`；可通过本机 `PI_MODEL` 指定其他模型。发送的问题、选中的知识及工具结果会传给 DeepSeek，请只输入合成内容。默认关闭思考，页面可选择已启用的 `low` 或 `high`；每任务最多 10 次模型派发、120,000 已知 token 和 120 秒。用量由服务返回，失败或未返回时为未知，不自动重试。模型兼容性和自主分析能力需通过真实调用验证，本机脚本测试不能证明。地址仅允许官方 `https://api.deepseek.com`，不跟随重定向；配置检查不是对数据库内容的密码学证明，请勿向该临时栈注入真实数据。

官方 DeepSeek 派发还必须先显式启用一个持久预算范围，例如：

```sh
npm run budget -- activate example-20261104 10 180000
export DEEPSEEK_BUDGET_ID=example-20261104
export DEEPSEEK_BUDGET_MAX_REQUESTS=10
export DEEPSEEK_BUDGET_MAX_TOKENS=180000
npm run demo:stack -- --deepseek
```

范围在本机 `.local-runtime/deepseek-budget.sqlite` 中以独立事务记录并由所有本机 worker 共享；任务重启不会清零。`npm run budget -- status example-20261104 10 180000` 以只读方式查看保守预留和服务商自报用量，已关闭的范围也可审计，不会重新激活：`requests_reserved` 是预留次数上界，未知或取消的调用仍占额，输入/输出和缓存分项缺失时不能当作零。token 预留是估计，不能作为精确费用上限，请以供应商账单为准。停止所有相关进程后可显式运行 `npm run budget -- close example-20261104 10 180000`，再用新 ID 和需要的限额创建新的日常预算；有未知用量时关闭需额外提供 `acknowledge-unknown`，不会删除旧账本。中断仍处于 pending 的请求需要先确认相关进程已停止并核对供应商账单；`status` 会显示前 100 个待处理 step ID，可用 `npm run budget -- acknowledge 范围ID 请求数 token数 step_id` 明确保留为用量未知，不能通过重启或重新激活清零。任务状态在 MySQL，总预算和任务状态属于两个独立事务，异常时可能保守占用两边额度，绝不据此自动重试。任务用量区分模型尝试、明确未派发、成功结算和结果或用量未知；因为进程可能在数据库标记后、实际网络请求前崩溃，“可能已派发”是保守上限，不能冒充精确网络调用数。明确未派发不会抹掉同任务已收到的用量。


配置示例在 [`.env.example`](.env.example)。不要把真实密钥写入仓库。`MODEL_MODE=deterministic` 是确定性演示；`MODEL_MODE=pi` 使用 Pi AgentSession，可选择显式 `faux`、`openai-compatible` 本机服务或显式启用的 DeepSeek 官方服务。Anthropic 和其他远程 HTTPS 供应商当前禁用，不会自动回退到 faux。

本地文件写到 `.local-runtime/`，该目录已被忽略。合成业务库存 `lumenfox.sqlite`，每次启动重建并以只读方式打开。

有两种本地模式，不要混称：

- `npm start` 是 SQLite 单进程演示。业务查询打在本地 SQLite，状态也在本进程。这不是 ClickHouse 验证。
- `BUSINESS_ENGINE=clickhouse` 时，业务查询打到 `127.0.0.1` 上的隔离 ClickHouse，使用只读账号。表卡在 `knowledge/harborlight/`。MySQL 仍只存任务状态，Redis 仍只做调度。不要把 SQLite 演示说成 ClickHouse 验证。

## 这条主链做什么

一次提问会经过：

1. 确定性演示模式会把用户原话编译成已发布语义文件里的槽位。`MODEL_MODE=pi` 把用户原话和同会话历史送进同一个 Pi AgentSession，不在模型调用前强制套用这层槽位，也不会在缺少密钥时退回演示逻辑。向模型发送后续轮次时，已交付的旧查询预览会压缩为范围摘要，旧分析保留服务端结果摘要；原生 JSONL 保留完整回执，历史摘要不能作为当前任务的证据。
2. Pi Agent 循环调用 8 个工具：`search_assets`、`read_asset`、`read_assets`、`read_data_contract_view`、`query`、`calculate_session_cells`、`read_session_resource`、`update_analysis`。
3. 搜索返回资产卡片与授权正文的命中片段，稳定续页校验结果哈希；正文只参与当前主体可读资产的检索匹配。`read_assets` 可批量读取各资产的 Unicode 码点分页，逐项检查内容哈希；契约字段可分页并显示已发布新鲜度。查询资源可按行和列分页，资源截断与页面续读分别标记。
4. `query` 在只读连接上解析单条 SELECT，并递归检查 CTE、子查询和联合查询里的表、字段、敏感列、契约版本和封闭日期。单表日期支持等值、`BETWEEN` 和上下界；宿主另限制 SQL 为 64 KiB、日期范围为 400 天，超出拒绝。JOIN 检查登记键与契约粒度；无法确定粒度及不支持的语法会被拒绝。严格限定的单事实表与维表 INNER / LEFT JOIN 子集在查询中捕获证明元组，检查事实粒度、实际类型、重复键和结果，并将实际匹配的维表键值与已发布的维表摘要核对；标签筛选之前检查维键重复。LEFT JOIN 固定启用 join_use_nulls，未匹配键须被完整发布快照证明缺失，结果保留 NULL；执行 SQL、设置及捕获结果共同绑定。单层单表 CTE 或派生表仅在内外都是直接投影、过滤仅在内层且可独立证明等价时可进入证据；实际仍执行原 SQL。受限单层 CTE 或派生表可先按事实契约粒度的子集预聚合最多八个受限整数或 Decimal SUM，再关联登记维表并求和；须保留登记键并逐个已观察事实键验证整段日期覆盖和唯一性；系统保存用户原 SQL，实际执行经过严格等价展开且附证明元组的 SQL，验证使用实际执行记录。不满足约束的形状拒绝。ClickHouse 模式先用 ClickHouse AST 发现候选物理来源。对单个物理事实表及可证明的封闭日期扫描，原项目 reviewer 的适配版可直接根据当前契约授权，记录 `clickhouse_ast_direct`；扫描授权与业务覆盖分开，额外谓词无法证明覆盖时明确标为未知；多层直接投影及受限列重命名 CTE/派生表可记录 `clickhouse_ast_scoped`（别名冲突与无法证明的作用域拒绝），实际执行原 SQL，内部另推导证明形状。预检、只读账号、查询预算和发布新鲜度仍然生效。受限物理事实—维表 INNER/LEFT JOIN，以及单层受控预聚合和多层一对一投影包装的 JOIN，可由 ClickHouse AST 和登记键规划证明，记录 `clickhouse_ast_join`；其他未迁移形状仍依赖受限 SQLite 方言策略。部分证据和计算仍使用旧解析器，这不是完整 ClickHouse AST 迁移，也不是任意 ClickHouse SQL 支持。事实表直接 JOIN 暂不支持。维表探测记录的是受限字段的观察摘要，而不是跨表原子快照，缺少有效回执或无法证明时失败关闭。单事实表的受限整数及 Decimal `SUM`、非 NULL `COUNT` 和最多三个契约维度分组可验证已捕获值；未出现的组合不补零。对直接返回原字段的 `isNull`／`isNotNull` 辅助投影，服务端逐行重算标记，只展示契约原字段；缺原字段、标记不一致或其他表达式仍不能作为可信结论。 受限 `countIf` 可查询直接授权列与常量的条件，NULL、非 NULL、零和直接数值字段与安全整数阈值比较的计数有独立证据验证，NULL 不满足数值比较，缺口时部分交付；小数阈值、复合谓词及其他未证明形状不因此获得证据；日期投影可执行不代表可以形成可信结论。受限 `sumIf`、`ifNull` 和 `nullIf` 表达式可在原生授权后作为有类型的查询观察供数学计算；业务指标名称、单位及自然语言含义未认证。显式空值替换不代表观测零，浮点观察及其派生结果标为近似且部分交付。已验证且完整的分组 `SUM` 可再次用定点数汇总；计数和零计数描述结果分组，不冒充事实明细计数。
5. 服务端根据证据决定终态。模型写出的“已完成”不会单独生效。契约声明了粒度时，无记录、值为 NULL、观测零和预测值分开；无记录和 NULL 不会补成零。存在这些缺口或覆盖情况未知时，数据结论是部分完成。覆盖统计目前仅能证明单表、日期上下界及序列维度字面量等值筛选；其他筛选或多表查询标为未知。自然结束时模型可选择本任务的结果并明确指定比较；宿主可比较两个本任务计算单元，或两个可唯一定位的 Decimal 汇总输出：要求完整覆盖和相同口径，范围只能差一个维度或两个等长不重叠日期段；差值用定点整数运算，比例保留四位、变化率保留两位，半数远离零，零基准不计算比例和变化率。原有浮点金额仍只是近似值。查询只读已发布的新鲜度快照，不在提问时用最大日期冒充。身份来自服务端标明的 mock 主体，不信任请求正文里的 userId。

契约视图只展示当前主体有权读取和查询的派生指标及登记关系；它们只是口径提示，不会自动绑定其他表。并发读取契约按会话和表在状态事务中合并，MySQL 写入还会检查主体、租约和 fence。单行明细的执行 ID 可从当前任务保存的资源回读；不同指标的逐行计算要求同一个已验证资源和同一行、契约声明的运算与相同范围。不同来源可使用受支持的聚合与对齐，不被当作共同快照。

ClickHouse 结果按行和字节上限流式读取：预览缩短不会截断已保存结果；超过保存上限时标记截断，观察到的行数只是下界。SQL 中的 `LIMIT` 也不视为完整总体。单元计算可使用完整资源，Decimal 明细在物理类型及契约可核验时按字符串精确求和；全 NULL 和无行求和不是零，未知预测状态不伪装为实际值。

新建的单资源计算绑定完整来源哈希；旧计算如果没有此绑定，不能继续作为本轮可核验证据，需重新查询并计算。交付可只选择最终资源，服务端会在本次评估中展开依赖并检查会话、任务及来源；循环或超限依赖会被拒绝。新建变换和对齐有独立计算执行 ID，可选择指定行或整列合计继续参与四则，结果单独标为数学运算而非已认证业务指标；输入缺口会向后传播。分组汇总的 `IN` 集合暂不支持进一步四则运算。

受限预聚合 JOIN 可穿过最多八层一对一列投影和重命名；投影层上的分组键字符串等值过滤可以沿已验证的列血缘下推，其他过滤、排序、额外聚合或截断仍不能被折叠。详细证明超过预算或不能验证时，可重新执行一个只读的聚合级证明：数据库对本次观察的事实粒度、维键重复和 NULL 指标做全量检查，并保存有界维表观测及实际执行回执。一般情况下它不证明缺失日期或未出现的分组，只按覆盖未知部分交付。契约若明确声明有限封闭维度域，且查询范围、域成员、去重与预期日期的全量数量均得到同次验证，可证明该封闭范围的覆盖；无法证明则仍是部分完成。域只代表契约明确声明的集合，不代表所有可能的业务对象，多次查询也没有共同快照保证。

ClickHouse 查询的日期边界可使用单参数常量 `toDate('YYYY-MM-DD')`，该日期必须有效且处于 ClickHouse `Date` 范围内；动态参数、多个参数和 SQLite 路径均拒绝。它只是受限语法支持，不代表已有完整的 ClickHouse 方言解析器。

受治理的 ClickHouse 业务查询在执行前使用同一只读客户端做固定的 `EXPLAIN PLAN`，预检超时、错误或结果不完整时不会继续执行该查询；计划文本不作为业务结果保存。EXPLAIN 不能代替现有授权、契约和日期检查，也不能证明跨查询具有共同快照。

封闭域使用契约 `series.coverage_domains` 声明，支持维度的有限字符串 `values` 或安全前缀与整数范围，例如 `{"country_code":{"prefix":"S","start":0,"end":12499},"channel_id":{"values":["mist_ads","pebble_net"]}}`。它是可信的完整性约定，不能由模型或查询自行声明；只有真实适用于整个相关契约范围时才能配置。测试会在临时复制的合成契约中声明该域；默认演示知识未声明，所以相同大样本默认保守显示部分完成。

四则运算可引用本任务受支持的聚合单元、完整明细的指定行或整列，以及已验证计算结果；明细引用须匹配执行 ID，交付时递归核对资源、权限、契约、新鲜度、覆盖和结果。跨指标公式只接受契约明确声明的有向关系与兼容口径；除法保留 18 位小数，半数远离零，除零返回不可计算。已验证 JOIN、聚合和受限直接投影支持结构化筛选、列比较、排序及分组变换，也可按键全集对齐，缺组和 NULL 不补零。单表直接明细可先在服务端基于全部哈希绑定分页按契约维度精确汇总再跨资源对齐；一侧也可使用经核验的数据库分组 SUM。该路径区分 NULL 键与字符串、全 NULL、部分 NULL、缺侧、零和零分母，输入覆盖不完整会随派生结果传播为部分完成；NULL 键的周期覆盖不能证明，因此保守降级。跨事实表仅接受契约显式声明的有向指标关系、相同维度类型和粒度与一致范围；不是用户归因。完整资源计算及各中间结果最多 10,000 行、2,000,000 字节和 10 步；默认查询保存上限同为 10,000 行和 2,000,000 字节，模型和页面只收到标明总数的有界预览，可按资源续页。明细变换限于受支持整数或 Decimal、契约声明仅观察值的直接投影；不支持的表达式、浮点及无法证明预测状态的输入会拒绝，而非样本冒充完整结果。普通 ClickHouse 查询与覆盖是独立读取，多次查询之间无共同快照保证；满足现有检查时可以完成交付，同时说明这个限制。同范围覆盖观测实际冲突时只能部分交付。模型自然结束时必须明确选择本任务成功回执中的最终结果；宿主追溯其依赖，不会自动把所有探索资源拼成结论。没有合格选择时可在原会话给出一次受限反馈；仍无有效候选则失败。

已验证 JOIN 结果可逐行执行契约明确声明方向的加、减、乘、除；两个完整资源也可按兼容键对齐后使用已声明的跨指标关系。默认合成收入契约的 r4 新增了“收入减成本”；旧 r3 绑定或来源不会自动升级，需要重新读取契约并查询。数据库聚合结果的日期键对齐仍有限制。

`update_analysis` 只更新模型自报的范围、粒度、问题和假设，不结束任务；这些内容在页面独立标明为工作记录，不作已验证事实。模型自然结束时以 `[[result:资源ID]]` 选择最终结果，或以 `[[clarify]]` 开头提出澄清问题；必要的单元比较以 `[[compare:左资源ID.列名,右资源ID.列名]]` 明确指定。工作记录从当前任务活动分支的匹配工具回执恢复，不跨任务继承为权威。模型解释单独显示并标明未经逐句核验。知识摘录须与当前可读资产的内容哈希和原文匹配，但不证明摘录适用或此前已读；结果单元引用须属于本任务的完整授权直接投影且匹配执行 ID，由服务端取值。知识目录、权限、JOIN 规则及相关资产文件会在读取、计算与交付前异步重核；文件检查与后续操作不是原子事务。终态提交前会重新核对候选记录所引用的资源哈希、授权、契约和已发布新鲜度；旧版未包含资源哈希的中断候选无法通过此检查，需要重新执行，不会悄悄升级为已核验结果。

知识在 [`knowledge/lumenfox/`](knowledge/lumenfox/)，区分资产目录、表契约、指标口径、分析 SOP、示例 SQL 和权限政策。`registry.json` 里的 `registry_revision` 和各资产 `revision` 是修订标识。

## 明确还是模拟的部分

本地实现有可替换的 `StateStore`，默认是单机 SQLite。这不是分布式生产方案：

- 保证限于同一台机器上的一个状态库。领取使用 `BEGIN IMMEDIATE` 和递增围栏号；心跳只续当前围栏的租约。
- 进程重启后，租约过期且尚未终态的任务可以被新执行者回收。旧围栏不能再写事件或终态。
- SQLite 演示没有多机共识。MySQL 模式的终态由事务和围栏保证只有一个；outbox 到 Redis 是至少一次投递。worker 在写完终态前崩溃时，合成查询可能再执行一次，这不是整个外部副作用的 exactly-once。
- SQLite 状态模式的新鲜度仍发布到本机文件。MySQL 状态模式由独立探测进程先登记批次，再把整批结果和发布指针写入 MySQL 事务；查询和交付只读取 MySQL 发布版本，数据库不可用、版本缺失或契约/目标清单不匹配时失败关闭，不回退旧文件。`/api/health` 的 `freshness_status` 区分已发布、未发布、清单变化和不可用；已发布不代表每张表都是 fresh。旧文件不会自动迁移，需要对隔离库重新探测。
- MySQL freshness 通过数据库分配的批次序号决定先后，较早开始的批次不能覆盖较晚批次。已发布版本及未完成批次保留供排查，本构建不自动删除历史。最终终态事务锁住发布指针并核对可交付证据版本，与发布事务排序；版本已变时任务失败且不保存旧结论。事实表探测核对日期是否存在；NULL、真实零和预测状态由后续查询覆盖检查区分，日期存在不证明指标完整。维表探测对声明的非敏感列最多读取 1000 行及 2 MB，检查键唯一后发布键值摘要；该观察时间不是外部同步时间，也不能证明数据库不可变。过期判断默认采用当前时间及知识包/契约时区，`SIMULATED_TODAY` 只用于注入合成测试日期。默认目标仍是固定合成日期；可选的 `knowledge/harborlight/freshness-targets-rolling.example.json` 使用契约时区、延迟和窗口计算周期。跨日时旧版本清单不再匹配，须重新探测；固定历史数据没有覆盖新周期会标为不新鲜。终态事务尚未原子复核跨午夜有效期、契约文件变更或主体权限变更。
- 业务库可以是本地只读 SQLite 演示或隔离的本地 ClickHouse 合成库；MySQL 只存任务状态，Redis 只负责唤醒。
- 确定性模型走 Pi SDK 的 faux provider，不发网络请求。`MODEL_MODE=pi` 可显式连接 DeepSeek 官方 API；已用有限的合成问题验证基本查询和同会话追问，不能据此推断其他分析场景或真实业务数据可用。
- 独立 API、dispatcher、worker、Pi 快照与领域工具使用 Promise 状态桥；MySQL 旧同步入口立即拒绝调用，SQLite 演示保留本机同步实现。单桥最多 64 个在途请求，超时或关闭时相关写入结果可能未知，桥会失效，后续由运行时重建；不能假定事务回滚或盲目重试。模型派发先预留、结算后才交付终止事件；Pi 快照按序等待保存，续租不重入。MySQL 租约和保护性写入使用数据库时间。进程内订阅只通知本 worker，不替代可持久续读的 MySQL/SSE 事件；异步不保证数据库故障或容量耗尽时仍低延迟，也不等于多机高可用。
- 知识正文及搜索匹配片段的 UTF-8 字节预算按会话持久保存；MySQL 模式在同一事务中核对有效租约及 fence，提交结果未知时不返回正文，当前执行器不会再次预留。进程崩溃后未完成工具调用可能按既有恢复规则重放并再次占额，预算不会因此扩容；无法断言旧页是否已送达。SQLite 模式使用本地状态库。升级之前已经发生的正文读取无法追溯，新计数从升级后的首次读取开始；首次设置的会话上限不会因提高配置而重置，工具调用和模型预算另行持久化。JOIN 捕获内容的哈希只是内容标识，信任状态库，不能防止有权写状态库的人同时改写证明和哈希。
- 客户端断开只停止事件流。用 `after` 序号可以有序续读已经落库的事件。取消必须调用取消接口。

MySQL 分进程模式需要先配置本机隔离 MySQL、Redis 和 ClickHouse，并准备合成数据与只读账号；按照 `.env.example` 为各进程设置相同的本机配置后，先运行 `npm run start:freshness`，再分别运行 `npm run start:api`、`npm run start:dispatcher` 和 `npm run start:worker`。首次使用 MySQL 需要允许初始化状态表与 freshness 表。也可使用上面的 `npm run demo:stack` 创建并清理本次隔离演示资源；手动停止服务和清理测试实例时应只处理自己创建的资源。

要试用滚动示例，所有进程需一致设置 `KNOWLEDGE_DIR=knowledge/harborlight` 和 `FRESHNESS_TARGETS_PATH=knowledge/harborlight/freshness-targets-rolling.example.json`，然后重新运行 freshness 探测。固定合成仓库可在测试中设置 `SIMULATED_TODAY=2026-10-29`；不设置则使用当前日期，不会把旧数据冒充当前数据。

也可用 `npm run seed:clickhouse` 在**本轮新建、回环端口的隔离 ClickHouse** 内建立新的滚动合成库。先通过环境变量提供 `CLICKHOUSE_URL`、`SYNTHETIC_DATABASE`、`SYNTHETIC_ADMIN_USER`、`SYNTHETIC_ADMIN_PASSWORD`、`SYNTHETIC_READER_USER`、`SYNTHETIC_READER_PASSWORD`；数据库和只读账号名须以 `synthetic_` 开头，口令使用本轮临时生成的字母数字。该命令只创建新数据库及只读账号，不清空或覆盖已有数据库；失败时保留部分初始化结果供检查。接着将应用的 ClickHouse 库名、只读账号与口令指向新库，再启动 freshness、API、dispatcher 和 worker。生成器默认按洛杉矶当前日平移完整合成样本，保留 NULL、真实零和预测；`SIMULATED_TODAY` 可固定测试日期。滚动窗口的示例延迟是合成规则，并非实时业务数据。

仓库里的 `showoff/`、`data_agent_plan/`、`da_assets/` 和 `bugfix_doc/` 是历史公开材料。它们帮助理解边界；和当前 TypeScript 主链冲突时，以这里的运行代码和测试为准。
