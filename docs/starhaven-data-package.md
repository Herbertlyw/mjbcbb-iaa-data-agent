# 第二版数据包的实现与交接

本次交付是 VV Data Agent 合成业务数据底座，不替换现有运行时。三款游戏命名为拼格 GridFit、落块 BlockFall、叠叠乐 StackJoy；代码标识为 `gridfit`、`blockfall`、`stackjoy`。新增 `synthetic/starhaven`、`knowledge/starhaven`、一项宿主知识测试及本文档；不覆盖原有未提交修改，不改变依赖、锁文件或既有知识目录。

详细操作见 `synthetic/starhaven/README.md`。

## 保留的结构优势

DDL、契约、表卡从同一字段定义生成，避免列名、单位、NULL 和粒度分别漂移。生成器的公开层只包含分析必需的聚合，既不依赖公司数据，也不需要持有真实用户身份。

每次发布包含版本、配置与实现哈希、表行数与文件哈希。导入只创建新数据库；版本切换、旧版本保留和回滚由调用者显式管理。对账不通过的数据不会被导入器接受。装载与 freshness 发布分开，避免生成完文件就假装可供正式分析。

模拟过程保留足以产生跨表关系的设备日状态；不同报表口径仍然分开。媒体注册不与设备首装硬凑相等，AF 收入不与 SDK 收入硬凑相等，重复窗口和基数也不强行变成可加指标。

## 本地验证边界

Python 测试检查结构、确定性、版本演进、反例和关键口径；宿主 TypeScript 测试检查知识加载和实际 ClickHouse 授权入口。原生 ClickHouse 另外执行 DDL、灌数、全部列类型、跨表 SQL 与示例查询。HTTP 导入测试启动自己的临时回环服务器，检查 23 表计数、只读拒写和拒绝覆盖已有数据库。

这些证据属于数据包验收。它们不能替代另一台电脑的 24.8 容器验证、MySQL/Redis/Pi 分进程流程、浏览器操作或真实 DeepSeek 自主分析。也不证明多次 ClickHouse 读取共享跨查询原子快照。

默认生成过程包含有解释的来源延迟，个别最近安装范围可标记 partial。回收表是有活动设备日的稀疏投影；必须结合处理范围和到达截止解释缺行。对账通过表示结构与已声明口径守恒，不代表每个指标窗口都已成熟。

## 另一台 Codex 的执行次序

1. 核对基线和当前工作树，保留所有原有工作。不要求清空暂存区，不重置、不 stash、不提交。
2. 校验交接补丁和逐文件 SHA-256。新增路径若已存在且内容不同，先报告具体冲突；不能覆盖。
3. 对新增文件执行应用检查，应用后核对哈希，执行 Python 测试、生成文件漂移检查、宿主知识测试和类型检查。
4. 创建本轮自己的隔离 ClickHouse，用 tiny 数据运行真实 DDL/灌数/对账和只读导入检查。记录实际版本；不要把本机 26.11 结果记成另一台 24.8 通过。
5. 在相同隔离资源中生成 demo 或 standard，使用新库、只读账号和绑定版本的知识目录。先发布 freshness，再进行宿主业务测试。
6. 先验证获客、活跃、广告收入、同口径成本和简单维表名称；再验证留存、跨来源对照、实验、预测和非加性字段。宿主不支持的认证形状需要单独列出，不能把数学结果伪装成业务事实。
7. 汇报数据包接收、对账、宿主集成和模型评测四种状态。不得把“40 道设计题”写成“40 道真实模型通过”。

## 尚未承诺的能力

本包不制造 IAP 支付业务、不实现完整游戏引擎，不推断未确认的第三款游戏玩法，不生成任意数量的账户和真实广告素材文件。它提供的是可复现的 IAA 游戏经营分析场景。

生成器当前重建完整新版本，不是低延迟流式 CDC。scale 档和任意参数组合仍受行数、设备数、内存及数据库执行预算约束。当前公开哈希提供一致性检查，不替代签名、认证或数据库写保护。

线上统一认证复杂窗口、重复 cohort 基数及预测语义，仍需要宿主理解相应规则。此次通过保守契约排除避免误认证，没有私自放宽现有证据门禁。
