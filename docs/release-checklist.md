# 候选版本验收

目标是可维护的本地合成数据分析版本：Pi 会话、只读 ClickHouse、异步状态、受治理计算和可查看证据的页面。此范围不承诺任意 SQL、生产认证、多机高可用或跨数据库原子快照。

本轮基于 `1325661ec2881bdc2321cad43067018313966988` 整理，交付方式是文本补丁，不创建本地提交或推送。应用补丁后需要重新验收接收方的最终文件状态，不能沿用旧提交的测试数字。

## 接收补丁

1. 核对基线和现有修改；不要覆盖未提交工作，不使用强制重置、清理或强推。
2. 在独立临时目录复制清单指定的当前工作树，用 `git apply --check` 检查完整补丁；增量不能直接套在不含此前实现的旧 HEAD。基线不同则按功能移植并保留现有修改，不能用忽略错误方式套入。
3. 应用后核对清单中的新增文件，特别是拆分出的领域服务和前端模块。
4. 不纳入 `.env`、密钥、预算账本、运行数据库、日志、依赖和容器数据。

## 离线验收

```sh
npm run typecheck
npm run knowledge-check
npm test
git diff --check
```

全量测试需要本机隔离 ClickHouse、MySQL、Redis。只使用测试新建的回环容器与合成数据；记录退出码、失败和跳过，并清理自己创建的资源。当前修改机器没有 Docker，只能运行不依赖容器的测试；此缺口不能用假客户端或 SQLite 通过替代。

必须保留以下反例：敏感字段、无界日期、非法 JOIN、过期契约或 freshness、其他任务资源、执行号错误、资源篡改、NULL、缺侧、预测混合、零分母、结果截断、旧围栏和未知供应商结果。失败用例不能通过放宽校验或删掉断言处理。

历史与本地可靠性另按 [历史分页验收](history-runtime.md) 检查：0／1／63／64／65／70／100 会话、200 条历史任务、同时间戳和新增期间分页、当前活动任务、主体过滤、历史授权、并发迁移、页面读取失败重试及 SSE 背压。MySQL 专项必须在真实本轮隔离库运行；本机 SQLite、浏览器或新增断言不能替代它。完整详情仍是按需读取，不以摘要通过宣称任意大任务响应已受限。

真实调用暴露的 C/F 修复须额外验收：

- C：支付表同一 SQL 在未读契约时返回 `missing_data_contract_evidence`，补读后成功；正式交付 1.00、2.00、−1.00 USD，不能残留该已纠正错误的 `unresolved_tool_failure`。不同 SQL 或未进入最终证据的成功不能清除该错误。
- F 独立读取：`SELECT title_id, title_name FROM dim_fox_title ORDER BY title_id` 不要求虚构业务日期；名称进入正式区并绑定本任务执行号和当前维表快照。名称变化但未重新发布、重复键、类型错误和缺主键不得认证。
- F 聚合 JOIN：按实际调用形状同时核对 `SUM(new_users)=70`、`countIf(new_users IS NULL)=0`、`countIf(new_users = 0)=0` 和 `count()=7`，包括常量 `toDate`、按产品名称分组排序及两个来源回执。原 SQL 与展开证明 SQL 的可见结果在固定合成数据上相同。后续对 `new_users_sum` 再求和仍须认证为 70 人，并保留产品名称和 JOIN 来源。
- F 分查路径：允许按已被等值筛选固定的 `title_id` 分组；返回键必须仍等于该筛选。分别查询事实与维表后，模型须明确选入计算和维表两侧资源。文本 `title_id` 不能以 `align_op=add` 伪装成名称关联；模型草稿提到名称不等于选入名称证据。
- 计数反例：同一组七行含一个 NULL、一个真实零时，`COUNT()` / `COUNT(*)` 为 7，`COUNT(new_users)` 为 6，NULL 与零计数各为 1。总行数单位为行，不能冒充人数；已存在 NULL 的 `SUM` 不因忽略 NULL 而升级成完整总体。重复事实粒度、重复维键、错误计数和未限定的同名字段继续拒绝。
- `tests/contract-retry-protocol.test.ts`、`tests/dimension-observation.test.ts` 和 `tests/f-real-shapes.test.ts` 使用脚本 HTTP 或假数据库传输。真实隔离数据库回归已加入 `tests/openai-clickhouse.test.ts`，包括原始 F SQL、查询后再求和、显式名称来源，以及真实 NULL 计数对照；接收方必须实际运行。本机无 Docker 的通过记录不能替代它。

真实 A 的日期写法须额外核对 `event_date IN (toDate('2026-10-08'))`：支付及投放两条原 SQL 不改写，扫描与覆盖都限定为同一天，正式区仍分别显示 1.00 USD、NULL 和 `null_input` 未知差额；缺数据的 `partial` 正确，但新任务不能再因这条受支持写法产生 `partition_predicate_unsupported` 或 `unresolved_tool_failure`。日期常量无效、动态函数、数组、子查询、NOT IN、错误限定符和 OR 绕过继续拒绝。旧的稀疏日期集合即使扫描范围有界，也不因此证明连续日期覆盖。历史 A 的失败记录不改写，也不把语义不同的查询错误一律清除。

真实 A 的分组聚合写法也须用原始 SQL 和整批计算参数回放，不能只重测直接明细或单日期 IN：

- 支付按 `title_id, platform, country_code, channel_id` 分组，核验 `SUM(amount_usd)` 的 Decimal 物理类型及 1.00 USD。投放另外按 `is_predicted` 分组，核验 `SUM(spend_usd)` 为实际标记 0 上的 NULL，保留 Float 原类型，不改造合成样本去迎合证明。
- 支付批次同时执行结果行数、NULL 数、零数和求和；投放批次同时执行结果行数、`actual_only` NULL 数及求和。带已存在列名的 `count_rows` 不能使整批失败，也不能被展示为底层业务行数。
- 分别回放“支付计算结果减投放查询单元”和“两边均先计算再相减”，使用本次回执中的资源与执行号。正式区须有 1.00 USD、成本 NULL 及 USD 口径的 `null_input` 差额；终态正确为 `partial`。不得残留此次兼容性导致的计算失败、未认证业务字段或单位。
- 保留错误类型、缺预测标记、未知标记、错分组、重复分组、矛盾计数、截断、跨任务、错执行号、契约/freshness 变化及计算后来源篡改反例。Float 非空值仍披露近似；不能把缺失覆盖上的数据库非空小计或全 NULL 输出零认证为完整实际合计。
- 本机传输回放在 `tests/grouped-a-evidence.test.ts`、`tests/unknown-arithmetic.test.ts`；真实隔离 ClickHouse/MySQL/Redis 与 API/worker 重启回读在 `tests/openai-clickhouse.test.ts`。未运行后者时必须明确记录缺口，不把其新增断言当作通过证据。

## 最终真实模型验收

VV 新数据的获客、计划、素材、收入、留存和 LTV／ROI 按 [业务体验](vv-business-scenarios.md) 单独验收，不用旧 Harborlight 金额充当新数据预期。先对已绑定发布运行 business-check，再核对 18 个场景的 22 条 SQL 和页面日期。脚本配方、数学复算、宿主业务认证和真实模型自主分析分别记录。旧 A–F 作为回归保留，不自动证明 VV 业务已通过真实模型。

仅在离线门槛完成、已有授权和有效持久预算明确时进行；不输出密钥，不重置或绕过已关闭预算。先冻结待验收文件，再读取本轮隔离合成库建立独立预期；不得把旧题目的金额沿用到另一成本口径。

主要验收题为：纸灯、美国、iOS、雾帆、2026-10-08 的支付流水、投放成本及支付流水减投放成本。

- 支付流水来自 `fact_fox_daily_payment.amount_usd`，预期为 1.00 USD。
- 投放成本来自 `fact_fox_daily_spend.spend_usd`，预期为实际记录上的 NULL，`is_predicted = 0`。
- 差额为未知；应保存绑定输入哈希、`value = null`、`undefined_reason = null_input` 的计算资源。已知流水和缺失成本必须各自进入正式结果区。
- `partial` 是本题正确的终态。缺失输入和非原子读取应披露；不得再因这个可复算的未知结果报 `arithmetic_lineage_unsupported`。
- 支付表的 `cost_usd = 2.00 USD` 是另一口径，不能替代投放成本。若单独验证 1.00 − 2.00 = −1.00，问题必须明确要求支付表的对应成本，并独立报告该题；它不替代主要验收题。

要求模型自主检索、读取契约、查询、计算和自然交付；只把业务问题交给模型，不提供预期答案、SQL、工具顺序或历史资源 ID。记录本轮实际派发数、服务商用量、完整终态原因和证据资源。若预算不足，报告未验收，不反复开范围。假服务按真实调用形状通过只能证明兼容性，不能替代真实结果。不得为了拿到“完成”删除限制说明。
