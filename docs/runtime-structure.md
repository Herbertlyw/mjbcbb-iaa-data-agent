# 运行时结构

本轮整理保留八个领域工具及其调用协议。`tools.ts` 只组合服务，权限不会因为模块拆分而另走一条宽松路径。

## 一次分析的职责

| 模块 | 职责 | 不应放入的内容 |
| --- | --- | --- |
| `tools.ts` | 组合领域服务，保留宿主调用入口 | SQL 解析、数值算法、答案排版 |
| `knowledge-tools.ts` | 搜索、正文分页、契约读取及持久预算 | 业务查询执行 |
| `tool-access.ts` | 当前主体、契约、freshness 与结果可读性复核 | 模型建议的权限规则 |
| `query-tools.ts` | 审查、执行、覆盖观测、保存查询资源 | 模型自由代码执行 |
| `query-observation.ts` | 从契约、SQL、物理类型和保存结果证明单个指标值或已知缺失 | 把保存行冒充完整总体、把 NULL 当作零或替换指标口径 |
| `aggregate-observation.ts` | 将受限单表 SUM/COUNT 分组转成带契约单位、预测标记及范围的统一结果输入 | 另一套求和算法、把输出分组数当业务行数、把 Float 恢复为 Decimal |
| `dimension-observation.ts` | 将独立维表查询的完整键及直接字段与当前发布快照逐值核对 | 根据列别名猜名称、将契约有效期当业务日期、证明未返回对象不存在 |
| `clickhouse-plan.ts` | 原生 ClickHouse 审查及版本化计划回执 | SQLite 解析失败后的兜底放行 |
| `result-tools.ts` | 校验计算请求并保存派生资源 | 另一套独立算术规则 |
| `result-evaluator.ts` | 本次评估内递归复算依赖，核对来源和保存值 | 跨请求缓存权限或 freshness 结论 |
| `result-policy.ts` | 契约声明的跨指标关系、方向及单位约束 | 根据列别名猜测业务含义 |
| `decimal-kernel.ts` | 定点运算、比较、精度与舍入 | 业务权限、业务指标认证 |
| `result-cells.ts` / `query-cell-input.ts` | 统一单元计算及查询输入适配 | 将 Float 恢复为精确 Decimal |
| `resource-reader.ts` | 完整保存资源的哈希绑定分页 | 把预览当成完整输入 |
| `analysis-delivery.ts` | 选择本任务证据，复核并构造交付记录 | 信任模型自报的完成状态 |
| `analysis-renderer.ts` | 将已证明的数据和限制排成文字 | 数据库访问、权限判断 |
| `join-resource-proof.ts` | 重核捕获的 JOIN 元组与维表观察 | 宣称跨查询原子快照 |

`tool-context.ts` 定义服务依赖和失败返回；`tool-preview.ts` 单独限制模型及 API 预览大小。`result-adapters.ts` 只把已证明资源转成统一结果表，不重新计算或扩大授权。`result-evaluation-context.ts` 的缓存只活在一次递归复核内。

宿主的 Pi、任务、快照、租约、预算及终态仍由原有 `jobs.ts`、`pi-session.ts` 和状态存储负责。`analysis-records.ts` 保留原有进程内记录和直接工具调用的修订回退；它不是 MySQL 权威账本。Pi 的 `update_analysis` 仍是工作记录，模型自然结束后的候选交付由宿主执行。

查询在读取契约前失败，可以在补读后重试。新进度事件仅保存 SQL 的 SHA-256 重试标识，不保存 SQL 正文。`candidate-failures.ts` 只在后续同一 SQL 成功、且成功资源属于最终选择的依赖图时消除一个缺契约前置错误；不同查询、旧版缺标识事件、授权失败和未选择的探索结果不因此消除。历史终态不会自动重写。

单事实表的单日期 `IN ('YYYY-MM-DD')` 或 `IN (toDate('YYYY-MM-DD'))` 使用同一天的封闭扫描与覆盖证明。ClickHouse 解析器会去掉单元素括号，右侧直接是日期字面量或函数；审查、扫描提取和覆盖提取都识别这一形状，实际 SQL 保持原文。该适配不支持动态日期或把稀疏多日集合当作连续覆盖，不改变旧任务失败的退休规则。

无日期分区维表使用独立的 `dimension_snapshot` 回执，记录发布身份、版本、快照哈希和观测时间。查询计划中的 `time_range` 在此仅保留契约有效期，并通过 `scope.kind=dimension_snapshot` 区分；协议和页面不将它展示为业务统计日期。只有含完整契约键、物理类型一致、每个返回值均匹配当前快照的直接投影可形成 `dimension_observations`。计数、表达式或缺键结果仍可在只读权限内执行，但不因此认证名称或业务人数；空结果不证明不存在。正式展示最多 100 条已核验键值，终态前再次复核。该快照仍是有界观测，不能证明跨查询原子性。

登记 JOIN 的计数证明区分四种操作：总记录行数、非 NULL 字段计数、NULL 计数和严格的字段等于零计数。总行数不读取伪造的指标列，统一结果中的单位是行；物理指标只在契约允许的范围内读取。详细元组中允许已声明可空字段参与计数，`SUM` 遇到缺失仍不能认证为完整合计；覆盖记录保留 NULL 日期。后续计算使用同一次 JOIN 的已核验统一结果，不进入仅接受单表契约的旧分支。

单表分组允许重复列出已由等值筛选固定的维度，但每行分组值必须匹配该筛选。分别读取事实结果和维表时，宿主不会因模型草稿提到名称而自动选入维表；模型须在自然结束时同时引用需要的数值和名称来源。`align` 仅处理可证明的数值指标，文本键加法依然拒绝。

带实际/预测标记的单表聚合先核对物理 SUM/COUNT 类型、维度与标记投影、结果完整性和重复分组，再适配为统一结果表；金额单位来自契约，标记值来自登记映射。后续 `cells` 整批计算仍交给 `result-cells.ts`，定点算术仍交给已有内核。查询单元带 `aggregation=sum` 时表示保存的数据库分组求和，不冒充一条原始业务明细。对聚合单元或其再次求和的 NULL 做跨来源运算，仍检查实际状态、物理粒度、日期、筛选、单位、当前任务与依赖哈希；只能证明未知运算，不能借此放行未声明的数值跨指标公式。已知覆盖缺口上的非 NULL SUM 仍不进入此业务适配器。

## 代码修改位置

- 新增 SQL 形状：修改原生 reviewer / plan 及对应证明适配器；同时验证授权与业务证据，不能只让 SQL 执行成功。
- 新增数学运算：先在定点内核和统一结果表实现，再声明允许的指标关系；不在工具或文字渲染层复制算法。
- 新增结果种类：补齐来源依赖、复算、哈希、分页和交付复核；历史资源不能成为新任务证据。
- 修改状态和恢复：继续使用异步状态 API、数据库围栏和结果未知语义；不在组件中另存一份终态。

## 浏览器模块

`web/index.html` 是语义布局；`styles.css` 是共享样式；`view.js` 只渲染并转义返回的数据；`stream.js` 独立维护 SSE 所有权、连续游标和重连；`app.js` 负责表单、导航和请求协调。

切换会话使旧流和旧请求回调失效；同会话查看旧问题时保留当前活动任务的独立事件连接，终态不会覆盖正在查看的旧问题。取消请求与浏览器断线分开处理。终态读取失败时，事件流从终态前一序号续读，而不是把未知状态当作完成。

页面优先展示服务端的结构化核验单元；没有适用单元时仍显示完整服务端答案。原文、限制、模型自报信息、SQL 和执行身份都保留。前端不从模型草稿提取数字来填结果表。

关联分组、指标和计数以宿主复核后的 `join_results` 展示，并匹配当前来源执行号；通用单元计算以 `calculations.verified_result` 展示；单表分组再次汇总使用 `calculations.verified_group_rollups`。这些结果直接进入正式区，不能因为同时有维表名称而将数值藏入折叠详情。原有 `cells` 和模型别名不会作为这些表格的填充值；完整文字结论及限制仍可展开查看。

`web-assets.ts` 仅发布固定白名单静态资源路径，其中 `examples.js` 管理业务分类、范围预览和填入交互，`history.js` 管理独立分页状态和迟到响应。没有通用文件服务器，也没有额外的前端依赖或打包阶段。

历史 HTTP 接口使用状态层的有界摘要投影；旧全量方法不进入页面列表。SQLite 和 MySQL 的稳定游标、MySQL 创建顺序及已有表迁移、活动任务判断和 SSE 背压见 [历史分页与事件续读](history-runtime.md)。`history-page.mjs` 是两个状态实现共用的线协议，`event-stream.ts` 负责有界发送；它们不改变模型预算、终态围栏或业务证据策略。

## VV 业务场景

`synthetic/starhaven/business.py` 是 18 个问题和 22 条 SQL 的维护来源；绑定数据时生成 `demo-catalog.json` 和 `starhaven.business` 业务 SOP。`vv-demo.ts` 只读取有界展示元数据，并与同目录 release.json 核对版本和日期；`GET /api/demo` 不返回 SQL、离线预期或数据答案，不创建 freshness、查询许可或任务。

`business_gold.py` 在离线生成独立 Decimal 预期，报告不注册到在线知识。显式 `native_business` 验证器通过临时 ClickHouse、真实工具、API 和 Pi 脚本检查配方；它使用现有 group／divide 与资源复核，不另建业务计算内核或绕过非加性字段规则。详细口径、接收步骤和验收边界见 `docs/vv-business-scenarios.md`。
