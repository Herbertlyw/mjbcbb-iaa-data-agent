# 历史分页与事件续读

会话列表只显示摘要，打开会话后再读取一页问题，选中问题后才读取完整结果。历史读取失败有独立的重试入口，不阻止初始化模型和新建会话；成功提交的问题不会因列表刷新失败而再次发送。

## HTTP 接口

| 接口 | 返回内容 |
| --- | --- |
| `GET /api/sessions?limit=25&before=游标` | `sessions` 摘要、`has_more`、`next_cursor` |
| `GET /api/sessions/:id` | 当前可访问会话的元数据与 `active_job_id`，不包含任务、槽位或契约绑定 |
| `GET /api/sessions/:id/jobs?limit=25&before=游标` | `jobs` 摘要、分页字段及独立查询的当前 `active_job_id` |
| `GET /api/jobs/:id` | 选中任务的完整详情；保留当前权限与契约变化后的历史答案隐藏规则 |
| `GET /api/jobs/:id/events?after=序号` | 按连续序号增量发送已保存事件；断开不会取消任务 |

会话摘要只有会话 ID、标题预览、主体、角色和创建时间，标题最多 200 字符。问题摘要只有任务 ID、会话 ID、状态、问题预览和创建时间，问题最多 240 字符；它们不含答案、事件、用量、模型上下文或供应商正文。要继续提问，应保留会话 ID；不要从问题预览还原完整原话。

旧版在会话列表及元数据中嵌入全部任务的响应已取消；调用方必须改用任务摘要接口。内部 `listSessions`、`listJobs` 仍供确有需要的运行时调用，HTTP 历史入口不使用它们，也不对每一项读取详情或检查分析。

默认每页 25 项，上限 50 项。省略 `before` 读取最新第一页；`next_cursor = null` 表示没有下一页。参数非法、游标跨主体或跨会话返回 400；无权访问的会话返回 404。空页与暂时不可用不同：状态桥过载、失效或结果未知返回安全的 503，不伪装为空历史。游标只是位置，不是访问凭据；当前身份仍是仅适合本机的 mock。

```sh
curl 'http://127.0.0.1:4317/api/sessions?limit=25'
curl 'http://127.0.0.1:4317/api/sessions/SESSION_ID/jobs?limit=25'
curl 'http://127.0.0.1:4317/api/jobs/JOB_ID'
```

## 稳定顺序和迁移

列表按 `(created_at DESC, id DESC)` 排序。第一页记录插入序号上界，续页同时应用该上界和最后一项的时间／ID；同一时间戳不会造成重复。第一页之后创建的记录，即使回填较早创建时间，也不进入这次翻页；刷新第一页后可见。标题和任务状态仍取读取时的当前值，因此这不是数据库 MVCC 快照或不可变业务版本。

SQLite 使用本机状态表的 rowid 和单写事务序列；系统当前没有删除会话／任务或 VACUUM 的后台任务。不要在有效游标存续期间用管理员 SQL 重排 rowid、改创建时间、删除并重建状态库。若之后增加历史清理，须一起设计持久序号及游标失效规则。

MySQL 为 `sessions`、`jobs` 增加自增的 `history_seq`。单靠 AUTO_INCREMENT 不保证提交顺序：低序号事务可能晚提交，穿入已开始的分页。`history_writers` 的两个固定行分别串行化两类创建事务，直到提交；事件、心跳、取消、供应商结算及既有任务更新不持有这层锁。任务创建保持 `session → history_writers → 插入任务` 的锁序。序号上界读取使用字符串，不改变其他 BIGINT 结果的既有解析方式。管理员直接写表和混跑旧版写入进程不属于这个创建协议。

两种状态库均补齐按主体的会话排序索引、会话内任务排序索引及活动任务索引。MySQL 初始化会对已有表实际补列、补索引，验证索引列顺序；并发启动只容忍明确的重复列／重复索引竞态，不忽略其他 DDL 失败。迁移会读取并可能重建现有表，先在自己的隔离库验收；升级时停止旧 API、dispatcher、worker 后统一使用新版本启动，不进行混合版本滚动升级。

每个会话列表页只有一个状态桥调用，任务页只有元数据和摘要两个调用，不随历史项数扇出。保留单桥 64 请求保护及超时结果未知语义；读请求可以由用户重试，不能把写入超时视为回滚或自动再次 POST。

## 页面所有权

`web/history.js` 管理独立的会话、任务分页状态和请求代次：加载、成功、空、失败均可区分；失败保留已有项和原游标；迟到响应、错误和 finally 不能污染另一个会话。翻页只取一页，按 ID 合并，不自动拉完历史。

模型／演示配置就绪后即可使用输入，不等待历史成功。浏览器保存的会话通过独立元数据接口恢复，即使它不在第一页。元数据暂时失败显示重试，404 才移除不可访问的选择。问题摘要暂时失败时，元数据里已知的活动任务仍可读取详情和取消。

活动任务来自服务端元数据及已成功提交的任务，不从已加载的历史页推断。查看旧问题时保留当前活动任务的事件连接和取消入口；其终态可以更新历史，但不覆盖用户正在看的旧问题。切换会话停止旧流，任务详情与分页请求分别检查当前所有权。创建会话或提问成功后先保留返回的身份，再独立刷新历史；历史错误不进入写入重试逻辑。

## SSE 读取边界

`after` 只能是有限的非负安全整数，非法值在发送 SSE 响应头前返回 400；超过当前最大序号也返回 400，等于已结束任务最后序号则正常结束空流。客户端应使用本次任务最后连续收到的序号，不复用其他任务游标。

状态层每次先读小型任务头，再按 `(job_id, seq)` 读取最多 32 条事件，限制为任务头已见的最大序号。SQL 不传输超过 64 KiB 的单个历史 payload，返回事件页在约 128 KiB 内；超大旧事件或序号缺口会安全拒绝，不跳过它们伪造连续性。此限制不删除或改写已有事件，也不限制被选中任务的完整详情响应。

`event-stream.ts` 一次只读取一页，`res.write` 返回 false 时等待 drain。客户端持续 15 秒不恢复写入则关闭连接，允许从客户端已收到的游标重连；断开清理定时器和监听，不继续轮询。活动任务尾部每 150ms 读取增量；有积压则页间让出事件循环。所有终态前事件发送后才结束流，不创造额外终态。发送 SSE 头后发生数据库错误会关闭连接，不把 JSON 错误或假事件塞进持久序列。
